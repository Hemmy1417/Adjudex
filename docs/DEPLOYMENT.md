# Deployment

## Contract

| Version | Address | Status |
|---|---|---|
| v0.1.0 | `0xDFA6B51565e17B677085351303F8397cd28Cb54D` | **current** — deployed 2026-09-01, source byte-verified against `contracts/adjudex.py` |

Deploy:

```bash
genlayer deploy --contract contracts/adjudex.py --rpc https://studio.genlayer.com/api
```

Verify the deployed source matches the repo byte-for-byte before pointing
anything at an address:

```bash
genlayer code <address> --rpc https://studio.genlayer.com/api
# diff against contracts/adjudex.py (ignore the CLI's trailing status line)
```

The header's blank line after the `Depends` runner pin is load-bearing: gluing
a comment to it makes GenVM reject the deploy as `invalid_contract` with an
empty stderr while every linter stays green.

## Web

Vercel settings:

- Root directory: `web` (the repo root's Python must never enter the build)
- Env: `NEXT_PUBLIC_CONTRACT_ADDRESS`, `NEXT_PUBLIC_GENLAYER_RPC_URL`,
  `NEXT_PUBLIC_GENLAYER_CHAIN_ID`, `NEXT_PUBLIC_GENLAYER_EXPLORER_URL`
  (copy `web/.env.example`)
- `NEXT_PUBLIC_*` is baked at build time: changing the contract address means
  changing the Vercel env **and redeploying**, and then reading the address
  off the live footer before trusting a demo.

Local:

```bash
cd web && npm install && cp .env.example .env.local && npm run dev
```

## Lockfile discipline

CI and Vercel run npm 10; a lock regenerated by local npm 11 can fail their
`npm ci` with phantom "missing from lock file" errors. After any dependency
change:

```bash
npx -y npm@10 install --package-lock-only --no-audit --no-fund
npx -y npm@10 ci --dry-run
```
